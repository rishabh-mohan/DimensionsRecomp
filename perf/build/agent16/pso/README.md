## 2.2: `pso-prepare-merged.diff`: recipe replay with PREPARE_THREADS>1

**What was serial at HEAD:**
1. **The default.** `PreparationThreads()` returns 1 when `LEGO_NATIVE_PSO_PREPARE_THREADS` is
   unset, clamped to [1, min(hw, 8)]. So by default the whole replay (library loads plus cold
   compiles) runs serially on the init thread. This is the main serial cost.
2. With threads>1, `PrepareParallel` already existed (RunOrdered workers, in-order commit).
   But it ran **once per source**: local recipes, then each seed file. Each call drains the
   window and joins the pool, and the next seed file is read (up to 128 MiB) while no worker
   is busy.
3. `commit()` (`Store()` of fresh compiles, `warmed_` first-512 admission, counters) runs on
   the calling thread in recipe order. This is kept serial on purpose, for deterministic
   library and file order and residency.
4. The dedup pre-pass and the "removed N seeded pipelines" rebuild are serial (cheap).

**Change:** with threads>1, `PrepareParallel` now reads every seed first, builds one job list
(local recipes, then seeds in `SeedPaths()` order, each name once) and runs a single ordered
pass. `seed_names_` is filled for every seed whose first job was reached, matching the serial
loop's "seeds reached, including the one it stopped in" on device removal. threads==1 runs
exactly the old code. The default stays 1. Agent6 measured library loads scaling only 1.07x
at 2 threads and 1.36x at 4, so the warm-boot gain is small and cold compiles gain most.
Change the default only after a functional row shows the gain.

**Behaviour differences (threads>1 only):** a name that failed in an earlier source is not
tried again from a later one (same name means same desc, so it would fail again), so
`failed=` can be lower than at HEAD with the same threads. All seed files stay in memory
together during replay. "using startup pipeline seed" lines are logged before the replay
instead of between sources.

## 2.3: `pso-unlocked-aux-save.diff`: aux compiles and Save outside `mutex_`

Already done at HEAD: the snapshot buffer is allocated outside the lock
(`pipeline_snapshot.h`, agent6 #1 part 1). Still under `mutex_` at HEAD:
`GetSerializedSize` + `Serialize` (#1) and the auxiliary `CreateGraphicsPipelineState` (#6).

- **Aux (`LEGO_NATIVE_PSO_AUX_UNLOCKED=1`, default off, latched once in `Open()` as
  `aux_unlocked_`):**
  - Unset: `Auxiliary()` runs the HEAD body, textually unchanged apart from one added
    `if (aux_unlocked_) return AuxiliaryUnlocked<kStats>(...)` line.
  - Set: `AuxiliaryUnlocked()` keeps `LoadGraphicsPipeline` plus hits/misses under `mutex_`
    (the D3D12 rule against two threads loading the same name), compiles with no lock, then
    `Store()` takes the lock.
  - Aux callers: device init (PRECOMPILE), the lazy `DepthResampler::Create`, and overlay
    `Pipeline()` for a new format. So the win shows with lazy creation or PRECOMPILE=0.
  - The env is separate from SAVE_UNLOCKED, so the two effects can be attributed separately.
- **Stop() (S1, always on):** `Stop()` now claims `saving_` with
  `compare_exchange_strong(false, true)`, sleeping 5 ms between tries as the old wait did,
  before its final `Save()`. A `Frame()` after that point fails its own CAS, so no second save
  thread can start, two Serializes never overlap, and two writers never race on
  `native-pso.bin.tmp`.
  - `saving_` is released on every path: the autosave thread always does `store(false)` after
    `Save()` returns (Save has only early returns, no throw paths beyond HEAD's), so Stop's wait
    ends.
  - Stop holds no lock while it waits, so it cannot deadlock.
  - `saving_` intentionally stays true after Stop: `StopPipelineLibrary()` retires (leaks) the
    object and never reuses it.
- **Save (`LEGO_NATIVE_PSO_SAVE_UNLOCKED=1`, default off):** `SnapshotUnlocked()` works like
  this:
  1. Under the lock: run the same `query()` and record `counted = unsaved_`.
  2. Outside the lock: allocate a fresh zero-filled `Capacity(size)` buffer, then query again.
  3. Outside the lock: `Serialize(data, size)`.
  4. Under the lock: accept only if Serialize succeeded **and** `GetSerializedSize() == size`.
     Then `saved = counted`, `unsaved_ -= counted` (stores made after the query stay unsaved
     for the next save), and `++saves`.

  On E_INVALIDARG or a size change, it retries with a new zeroed buffer and never reuses one.
  On another failure, or after 3 attempts (6 locked passes), it falls back to the old locked
  `SnapshotPipelineLibrary`. The fallback is logged at WARN, and the abandoned passes are added
  to the stats. Without a race the bytes come from the same buffer size, the same Serialize and the
  same write path, so the file is byte-identical. With the env unset, Save runs the old code
  (the query/copy lambdas are only reshaped).

## Risks

- **Fingerprint and cache state (B2):** `pipeline_library.cpp` is not an input to
  `LEGO_NATIVE_GPU_FINGERPRINT` (rexlego/CMakeLists.txt L604-786 does not list it), so a
  faithful build keeps native4bp's fingerprint 39129c4c059be5f0. Both A/B arms (native4bp-bin
  as reference, the PSO bin as test) share fingerprint and cache format, so they must start
  from the same cache state: both cold, or both seeded from the same unscored seeding run.
- **Env unset (A-n1):** with every env unset the code is HEAD, except Stop()'s `saving_`
  claim, which is always on.
- **Lock order:** the only locks are `mutex_` and RunOrdered's internal mutex, never nested.
  Prepare still touches `warmed_`/`stats_` without `mutex_`, as at HEAD (startup only, no Save
  can run then).
- **D3D12 thread safety:** the library is free-threaded except for concurrent loads of one
  name. Prepare jobs are deduped across all sources, and the aux load stays under `mutex_`.
  An unlocked Serialize runs alongside loads (agent6: allowed). A `StorePipeline` issued during
  Serialize blocks in the driver (115-204 ms) **while holding `mutex_`**, so loads queued behind
  that store still wait. This is a remaining limitation; the follow-up is to move StorePipeline
  outside `mutex_`. Behaviour of Serialize under concurrency on non-NVIDIA drivers (vkd3d,
  AMD, Intel) is unverified; the post-Serialize size check is the guard.
- **Conservative accept:** a store that lands after Serialize finishes but before the re-lock
  also rejects a valid copy. That costs a retry, and the fallback bounds it. Saves only run
  after `kQuietBeforeSave`, so this should be rare.
- **Duplicate aux compile (AUX_UNLOCKED only):** two threads missing the same aux name both
  compile, and the second `StorePipeline` fails harmlessly. The callers then hold two different
  PSO objects for one aux name. That is fine because each caller caches its own (noted in the
  code comment); the cost is extra CPU.
- **Recipe order and residency:** commit stays in order on one thread, so library store order,
  recipe file order and which pipelines get the first 512 `warmed_` slots are unchanged for
  the same set of successful names.
- **Memory (2.2, threads>1):** all seeds are resident during replay (each ≤ kMaxRecipeFileBytes).
- **Failure paths:** device removal stops at the failing job. A seed whose first job is after
  the stop point is not recorded in `seed_names_`, same as serial. 2.3 kNoMemory keeps the
  existing "save postponed" path.
