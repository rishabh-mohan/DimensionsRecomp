## Toypad
**Root cause: wrong colour to character map, not the emulator.** The user's rule is "Wyldstyle in the centre". Pad 1 (centre) pulses `F4 00 16 / 3D 00 05`, which is Wyldstyle. Pad 3 (right) pulses `F4 69 16 / 3D 1A 05`, which is Gandalf. The kit had these two swapped, so on each prompt it re-placed the wrong figure on the flashing pad, and the game waited out its ~120 s failsafe:
- pad 3 prompt 02:53:09-02:55:09: wyldstyle re-placed ×5, ignored;
- pad 1 prompt 02:57:25-02:59:25: gandalf re-placed ×5, ignored.

**Proof that post-boot events reach the game:** the Batman prompt (pad 2, `00 00 16/05`) started 02:52:12.155. The sidecar sent REMOVE at 02:52:13.288 and LOAD at 02:52:14.305. At 02:52:14.344, 39 ms later, the game stopped the prompt pulse (pad 2 → `00 00 0B`).
- In the 20:43 run, the boot Batman sat on pad 2 untouched and the same prompt pulsed for the full ~120 s (221 matching lines, against 5 here).
- So the game needs a fresh "figure added" event on the prompting pad, and it does receive one after boot.

**Why game.log showed "nothing after boot":** emulated_toypad.cpp logs only the first 64 reads (`Toypad[Read ]`, L247-251) and the first 256 writes (`Toypad[Write]`, L256-260).
- In this run the read cap was hit at 02:49:08.974 and the write cap at 02:53:25.671.
- From then on, no figure-added/removed event (a 0x56 read) and no D2/D4 command can appear in game.log, whatever the game does.
- The event path itself (LoadFigure/RemoveFigure push 0x56 onto `responses_`; ReadInternal pops it) has no state gate.

**Index offset:** the boot event shows `pad 02 index 01` for LOAD pad=2 index=0. That is by design: `figure.index = index + 1`, the 1-based slot reported to the game (emulated_toypad.cpp L741, header L60). It is not a bug.
