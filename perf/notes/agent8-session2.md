## 3. `native_scene_diagnostics` default: measured proposal (item 3)

### 3.1 What it does and costs
`REXCVAR_DEFINE_BOOL(native_scene_diagnostics, true, …)` at `native_skin_diagnostics.cpp:14`. Its help text reads "…in
this diagnostic development build". It is `kInitOnly` (toml or command line, read at start), and it exists only in the
Native GPU build. When ON:

| hook | when | cost when ON |
|---|---|---|
| `sub_82A33D28` (guest alloc) | every allocation | 1 journal `Record`: **+30 ns** (new code; was +51) |
| `sub_82A34208` (guest free) | every free | TLS save/restore + 2 `Record`s: **+65 ns** (was +104) |
| both, 2 threads allocating at once | contention | **~+400 ns per alloc+free pair**, old and new alike |
| `sub_82C9A000` (NuCpuSkin teardown) | per skin, at level unload | 9-16 log lines; text ~7 µs (was ~0.37 ms) plus spdlog |
| `sub_82E0F480`, `sub_82DD3220` (tree cleanup) | per call | copies 16-34 guest words |
| `sub_82A2AA28` (heap assertion) | only on a crash path | the full register, stack and history dump |

**Scale:** per 1,000 alloc+free pairs per frame, ON costs ~0.1 ms/frame uncontended and up to ~0.4 ms when contended.
The game's real allocation rate is unknown, and that is what the A/B measures.

**OFF loses:** the "Native heap assertion / history / free origin / block / stack" dump when the title's "Expected
allocated block" assertion fires (the Scooby-Doo crash class), the per-pointer heap history (the last 8 events per
bucket, 8192 buckets), the NuCpuSkin teardown logs and the tree-cleanup snapshots.

**OFF keeps:** the invalid-heap skip fix (`lr == 0x82CC0488 && r3 == 4`, which runs before the cvar check), the original
assertion and failure behaviour, and `native_load_heap::AllocationAttemptScope`.
