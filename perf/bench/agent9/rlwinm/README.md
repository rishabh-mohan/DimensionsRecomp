# rlwinm / rlwnm / rlwimi: 32-bit lowering and equivalence proof

Flag: `RecompilerConfig::rlwinmLowering` (TOML `rlwinm_lowering`, include/rex/codegen/config.h).
The flag is off by default; Agent 9 flips it. With the flag off the emitted text is byte-identical:
each builder has a new `if (ctx.config().rlwinmLowering)` branch at the top, and the old code
below it is untouched.

## Lowering rules
Let x = `rS.u32`, m = mask32(mb, me) (bits mb..me, bit 0 = MSB), n = sh. Only cases with mb <= me
are lowered. Wrap masks (mb > me) return nullopt and keep the generic 64-bit text, because there
the result's high word is the rotated word R rather than 0.

| class | condition (n = sh) | 32-bit expression | e.g. |
|---|---|---|---|
| copy | n = 0, m = ~0 | `x` | |
| mask | n = 0 | `x & m` | clrrwi |
| shl | m == ~0u << n | `x << n` | slwi |
| shl+mask | m inside ~0u << n | `(x << n) & m` | extlwi, insrwi |
| shr | m == ~0u >> (32-n) | `x >> (32-n)` | srwi |
| shr+mask | m inside ~0u >> (32-n) | `(x >> (32-n)) & m` | extrwi, inslwi |
| rotate | m = ~0 | `__builtin_rotateleft32(x, n)` | |
| rotate+mask | anything else | `__builtin_rotateleft32(x, n) & m` | |

Statements emitted:
- rlwinm: `rA.u64 = <expr>;`
- rlwimi: `rA.u64 = (<expr>) | (rA.u64 & <K>);`, where K = `~uint64(m)`. K is the same constant
  the old text uses, so rA's high word and every rA bit outside m are kept exactly.
- rlwnm: `rA.u64 = __builtin_rotateleft32(rS.u32, rB.u8 & 0x1F)[ & m];`. The count expression is
  the old one; `& m` is dropped when m = ~0. This matches the existing `build_rotlw` text.

Literals use the same text as fmt `0x{:X}`. Every expression has type uint32_t, so the store
zero-extends.

Why this is exact. The generic text is `rotl64(x | (rS.u64 << 32), n) & MASK(mb+32, me+32)`. The
low 64 bits of the doubled word are x:x, so rotating by n < 32 gives R:R with R = rotl32(x, n).
With mb <= me the 64-bit mask is zext(m), so the result is zext(R & m). In the doubled form,
rS's high word is shifted out, so it never matters. rotl32(x, n) = (x << n) | (x >> (32-n)), and
the two halves use disjoint bit sets L = ~0u << n and Rt = ~0u >> (32-n). So a mask inside L
keeps only `x << n`, and a mask inside Rt keeps only `x >> (32-n)`. For a fixed configuration,
both texts are GF(2)-linear in (rA, rS): the OR'd parts are bit-disjoint, so OR acts as XOR.
Agreement on 0 and on every basis vector therefore proves agreement on all 2^128 inputs. The
driver checks exactly that (walking-1 for rS; rlwimi also has e_i in rA with rS = 0). The other
inputs are extra. For rlwnm the count depends only on `rB.u8 & 0x1F` in both texts, and every rB
low byte 0..255 is tested.

## Exhaustive equivalence test
How it works:
- harness/gen.cpp includes the real rotate_mask.h. For each configuration it writes:
  - `o<i>(Reg& ra, Reg& rs[, Reg& rb])`: the old text, made with fmt from format strings copied
    verbatim from logical.cpp, plus a verbatim copy of helpers.h compute_mask;
  - `n<i>`: the flag-on text, `"\t" + lowerX(...)`. Where lowerX returns nullopt, the case points
    at o<i>, as the flag-on builder falls through to the old text.
- The output is split into 9 TUs. The cases are compiled with clang -O1 and the driver with -O2.
  Each case is run on old and new with identical full 64-bit registers. The driver compares new
  vs old and old vs an independent bit-loop model of the 64-bit ISA (harness/refmodel.h). It also
  checks that source registers are not clobbered.
- Inputs:
  - rS (399): 15 specials (0, ~0, 0x80000000, 0xFFFFFFFF, 0xFFFFFFFF00000000,
    0x0123456789ABCDEF, 0xAAAA.., 0x5555.., 0x8000000080000000, ...), walking-1 (64), walking-0
    (64), and 256 splitmix64 randoms with garbage in the high word. rlwnm uses the same set with
    32 randoms (175).
  - rA for rlwimi (12): 0, ~0, 0xDEADBEEF00000003, 0xFFFFFFFF00000000, 0x00000000FFFFFFFF,
    0x8000000000000000, plus 6 randoms (all nonzero high words except 0 and 0xFFFFFFFF).
  - rB for rlwnm (768): every low byte 0..255, each as clean, with random garbage in bits 8..63,
    and with 0xFFFFFFFFFFFFFF00 set. The aliased runs use the 192-value subset with low bytes 0..63.
- Aliasing:
  - rlwinm: rA = garbage (`~rS ^ 0x5A..`), and rA == rS.
  - rlwimi: every rS x rA pair, the basis vectors, and rA == rS.
  - rlwnm: distinct; rA == rS; rA == rB; rS == rB; all three equal.
- Sensitivity control. For each lowered case, new is compared against the old text of two wrong
  configurations (me+1 and sh+1). Every one of these wrong pairings must be detected, which shows
  the inputs can tell configurations apart.

Results (results.txt):

| instr | configurations | lowered | evaluations | new != old | old != ref | src clobbered |
|---|---|---|---|---|---|---|
| rlwinm | 32768 (all sh, mb, me) | 16896 | 26,148,864 | 0 | 0 | 0 |
| rlwimi | 32768 (all sh, mb, me) | 16896 | 174,161,920 | 0 | 0 | 0 |
| rlwnm | 1024 (all mb, me) | 528 | 208,369,664 | 0 | 0 | 0 |
| total | 66,560 | 34,320 | 408,680,448 | 0 | 0 | 0 |

- Sensitivity: rlwinm 33792 of 33792 wrong pairings detected; rlwimi 33792 of 33792.
- Configurations per class (the same for rlwinm and rlwimi): none (wrap) 15872, copy 1, mask 527,
  shl 31, shl+mask 5425, shr 31, shr+mask 5425, rotate 31, rotate+mask 5425.
- rlwnm: 528 masks with mb <= me are lowered. Only one of them (mb=0, me=31) is the full mask,
  which drops the `& m`. The 496 wrap masks are not lowered.
- `RESULT: PASS (0 mismatches)`

## x64 code (clang 23 `-O2 -march=x86-64-v2 -S`, Windows x64 ABI; instruction count excludes ret)
"locals" means the registers are function arguments or locals. "ctx" means they are fields of a
struct reached through a pointer (`ctx.rN`). xor is an alternative rlwimi text,
`ra.u64 ^= ((expr) ^ ra.u32) & m`. It was measured only and is not used.

| form | old (locals) | new (locals) | xor (locals) | old (ctx) | new (ctx) | xor (ctx) |
|---|---|---|---|---|---|---|
| slwi 4 | 2 | 2 | - | 3 | 3 | - |
| srwi 8 | 2 | 2 | - | 3 | 3 | - |
| clrrwi 4 | 2 | 2 | - | 3 | 3 | - |
| extrwi 4,25 | 3 | 3 | - | 4 | 4 | - |
| rlwinm 2,20,29 (shl+mask) | 2 | 2 | - | 4 | 4 | - |
| rlwinm 8,16,27 (rotate+mask) | 5 | 3 | - | 7 | 4 | - |
| rlwimi 2,0,29 | 4 | 4 | 4 | 6 | 6 | 6 |
| inslwi 8,16 | 4 | 4 | 4 | 2 | 2 | 4 |
| insrwi 8,16 | 4 | 4 | 4 | 2 | 2 | 5 |
| rlwimi 8,16,27 (rotate+mask) | 7 | 4 | 8 | 10 | 7 | 5 |
| rlwnm 16,27 | 7 | 4 | - | 10 | 6 | - |
| rlwnm 8,31 | 7 | 4 | - | 10 | 6 | - |

- clang already folds the old doubled-word text to 32-bit code for pure shift and mask forms, so
  slwi, srwi, clrrwi, extrwi, extlwi, inslwi and insrwi are unchanged.
- The gains are in rotate+mask (5 to 3 instructions), rlwimi with a real rotate (7 to 4) and
  rlwnm (7 to 4). In these cases the old text builds the 64-bit doubled word (`shl $32; or;
  shld/rol q`), while the new text uses one `shld`/`rol` on 32 bits. In no case is new worse than
  old.
- The xor rlwimi form is never better with locals, is worse for rlwimi 8,16,27 (8 vs 4), and with
  ctx it loses on inslwi and insrwi (4/5 vs 2). It only wins for rlwimi 8,16,27 with ctx (5 vs 7).
  So rlwimi keeps `(expr) | (rA.u64 & K)`.
- An earlier version of count_x64.ps1 also counted `retq` (+1 on every cell). That is fixed, and
  this table is the corrected run.

Example (rlwnm 16,27, locals):
```
old: movq %r8,%rcx; movl %edx,%eax; shlq $32,%rdx; orq %rdx,%rax; andb $31,%cl; rolq %cl,%rax; andl $0xFFF0,%eax
new: movq %r8,%rcx; movq %rdx,%rax; roll %cl,%eax; andl $0xFFF0,%eax
```

## tests/ppc/asm/instr_rlw_lowering.s
The file has 35 tests in the format of instr_rlwinm.s / instr_rlwimi.s. The test names are
`rlw_lowering.test_<op>_<case>`. Expected values come from the reference model and were
hand-checked. In every test rS has garbage in its high word, and rA starts as garbage
(rlwinm/rlwnm) or with a nonzero high word (rlwimi). Each test has a comment line right after the
label with the lowered statement. Tests are separated by blank lines, and there are no comments
between the instructions and REGISTER_OUT, as ParseTestSpecs requires.
- rlwinm (16): clrrwi (mask), mask 0,8,23, slwi 4, slwi 31, shl+mask 2,20,29, extlwi, srwi 8,
  srwi 31, extrwi, shr+mask 24,8,15, rotate+mask 8,16,27, rotate+mask 31,0,15, wrap 8,28,3 (old
  form, high word = R), rA == rS, and two record forms (`rlwinm.` GT, `rlwinm.` EQ, checked through
  `mfcr r12`).
- rlwimi (12): shl, insrwi, inslwi, mask, shl 16, shr, rotate+mask, copy 0,0,31, rotate 8,0,31,
  wrap, rA == rS, and `rlwimi.`. All of them have a nonzero rA high word, which must survive.
- rlwnm (7): rB = 40, rB = 0xFFFFFFFF000000F8 (garbage plus count 24), rB = 32 (count 0),
  rB = 63, wrap, rA == rS == rB, and `rlwnm.`.
- Record tests use results whose CR0 is the same under the 32-bit and the 64-bit compare
  convention.
- Encodings avoid the disassembler aliases (rlwinm mb=0,me=31 decodes as rotlwi, rlwinm sh=0,me=31
  as clrlwi, rlwnm mb=0,me=31 as rotlw), so every test reaches the three builders. objdump
  (ppc/objdump.txt) shows plain rlwinm/rlwimi/rlwnm.
- The old text equals the reference model on every input (old != ref = 0 above), so the file
  passes with the flag off too. It only exercises the lowered text once the default is on, because
  test_recompiler uses a default-constructed RecompilerConfig.

## Open items
- Wrap masks (mb > me) are not lowered: 15872 of 32768 rlwinm/rlwimi configurations and 496 of
  1024 rlwnm masks. The result there is R:(R & m). It could be lowered, e.g.
  `(uint64_t(R) << 32 | R) & MASK`, but that was not attempted.
- I did not build rexglue or ppc_tests and did not run ctest. That needs Agent 9's slot, with the
  default flipped to on.
- rlwinm copy and rotate, and rlwnm with the full mask, are effectively unreachable: the
  disassembler hands those encodings to build_rotlwi / build_clrlwi / build_rotlw, which already
  emit 32-bit text. They are lowered anyway and covered by the exhaustive test.
- The CR0 convention for record forms is unchanged; the same emitRecordFormCompare is used.
